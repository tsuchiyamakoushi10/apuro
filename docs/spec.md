## 2. 未確定項目の管理

`src/config/site.ts` に集約する。未確定値は `【調整中】` の文字列を入れ、画面上は青の点線下線で表示する。

**ビルド時に `【調整中】` を検出したら警告を出すチェックを入れる。** 未確定のまま本番公開されるのを防ぐため。

失敗させるのは公開スイッチ（`published = true`）が入った本番ビルドと、`CHECK_TBD_STRICT=1` を付けたときだけ。
`published = false` の間は確認用のデプロイなので、Vercel の Production でも警告のみで通す。

## 3. デザイントークン

```css
--paper:#FFFFFF;
--mist:#F4F8FA;
--blue:#2A6FA8;
--blue-deep:#1B4E7A;
--blue-ink:#123A5C;
--blue-soft:#DCEAF3;
--sand:#DFC9A5;
--ink:#2B3740;
--ink-muted:#69777F;
--r-lg:40px;
--r-md:28px;
```

**使用ルール**
- `--sand` は採用セクションでのみ使う。他のページに出さない
- 影は使わない
- グラデーションは使わない。例外はヒーローの可読性のための膜（`.hero-scrim`）のみ
- 角丸は `--r-lg` と `--r-md`、ピル型の3種類のみ。カードごとに変えない

**タイポグラフィ**

| 用途 | フォント | 指定 |
|---|---|---|
| 見出し | Zen Kaku Gothic New | 500 / `letter-spacing:.05em` |
| 本文 | Noto Sans JP | 400 / `line-height:1.95` |
| 英字ラベル | Jost | 400 / `letter-spacing:.16em` |
| ヒーローの英字 | Cormorant Garamond | 300 italic |

本文カラムは `max-width:34em`。コンテンツ幅 `1160px`、左右パディング `32px`。
ヘッダーだけ1300px以上で `1440px` / 左右 `40px`（`.wrap-header`）。

ヘッダーのナビと電話番号は1300px未満で畳む。サイト全体のブレークポイントは960pxだが、
ヘッダーは1行にロゴ256px＋ナビ339px＋電話・ボタン541px＋余白で1197px要り、
960pxまで引っ張るとノートPCの幅でナビと電話番号が重なる。1300pxで余白は23px。
畳んだ先は MENU（`src/components/MobileMenu.tsx`）で、電話番号もその中に入れてある。
MENU と開閉のしるしの▼はひとまとまりで右端に置く。左右の端に振ると別のものに見えて、開くものだと分からない。

開くと、ヘッダーの下に薄い白の面（`rgba(255,255,255,0.88)` ＋ぼかし10px）と文字が
なめらかに重なって出る。下のコンテンツを押し広げず、写真の上にかぶせる。
動きは opacity と translate だけ。`prefers-reduced-motion: reduce` のときは
globals.css がすべての transition を止めるので、この面も即座に切り替わる。

**リンクを押して遷移したら閉じること。** 以前は `<details>` でJavaScriptなしに開閉していたが、
App Router の遷移ではDOMが残るためメニューが開いたままになる。
`usePathname` の変化とリンクの `onClick` の両方で閉じている（同じページへのリンクは
パスが変わらないため）。Esc と、面の外を押しても閉じる。
閉じているあいだは `visibility:hidden` にしてタブ送りからも外す。
このサイトでクライアントコンポーネントを使っているのはここだけ。
ヘッダーの文字サイズを変えたら Chromium で測り直してブレークポイントを合わせること。

参照サイトの本文が17px・見出し34pxで、モックの値ではPCで小さく見えた。二段階で合わせている。

1. 基準値を一段上げた。10〜14.5px にばらついていた小さい文字を 13 / 13.5 / 14 / 15px の4段に整理し、
   h3 を 19px → 23px、h2 を 29px → 30px に。基準値なのでスマホ（960px以下）も同じぶん大きくなる
2. 961px以上で `html { font-size: 113% }` を掛ける（本文15px→17px、h2 30px→34px、h3 23px→26px）

文字サイズは `rem` で指定すること。ヒーローの文字とロゴのみ `px` のまま据え置く。
下層ページの h1（38px / スマホ26px）は元から大きいので上げていない。

**モーション**

参照サイトに合わせ、以下の4つだけを入れる。実装の決まりごとは `CLAUDE.md` の「モーション」を参照。

| 対象 | 動き |
|---|---|
| ヒーローの写真 | 3枚を18秒で1周するクロスフェード＋ゆっくり縮小 |
| スクロールキュー | ヒーロー右下で上下に揺れる |
| セクション・カード | スクロールで下から22px上がりながら現れる |
| ボタン・リンク・カード | ホバーで色が変わる。カード内の写真は 1.03 倍まで寄る |

特徴セクションの `position: sticky` によるスクロール連動は廃止した（カードは `.reveal` のみ）。JavaScriptは使わない。
登場アニメーションはスクロール駆動CSS（`animation-timeline: view()`）で書き、非対応ブラウザでは
最初から表示された状態になる。`prefers-reduced-motion` の指定があるときは一切動かさない。

### 原稿の改行

PCは原稿の改行位置をそのまま出す（`Lines` が1行ずつ `block` の `span` に入れる）。

**960px以下は改行位置を捨てて流し込む**（`Lines` の `reflow`。`span` を `inline` に落とす）。
原稿の1行は40字前後あり、スマホの幅では途中で折り返して2〜3字だけが次の行に残るため、
原稿の改行を守るほうがかえって読みにくい。本文の `Paragraphs` は既定で流す。
見出しは流さない。1文が長く続いて読みにくくなるため、原稿の改行のまま出し、
そのぶん文字を落とす（`/about` のミッション・ビジョン）。h2の30pxだと1行17字が入らず、
途中で折れて「地域を、」だけが行に残るので、960px以下は一段下げて19px（`1.1875rem`）。
600px以下はさらに (画面幅 - 左右32px) ÷ 17字 ÷ 1.05（字間.05em）まで落とす。
ヒーローの見出しと同じ考え方。**原稿の字数が変わったら計算し直すこと。**

流さないのは、改行が値の区切りになっている箇所だけ（`/recruit` の募集要項の表）。

## 4. ページ構成

### `/` トップ（5セクション）

1. ヒーロー（メインキャッチ＋サブキャッチ、写真は全幅・下角丸）
2. アプロについて（リード文＋写真＋下層への導線）
3. **特徴**（青ベタ面。見出しの下にカード3枚を横並び）
4. こんなときに、ご相談ください（3対象を各3行で。箇条書きは使わない）
5. 採用バナー
6. お問い合わせ（電話・お問い合わせ・採用エントリーの3枚＋アクセスマップ）

情報量を絞る方針。詳しい説明は下層に置き、TOPは「何をしている事業所か」と「どこに連絡するか」だけ伝える。

**お問い合わせ（`Contact`）**

窓口は3つ。お電話でのご相談・お問い合わせ・採用エントリー。960px以下は縦積み。
カードは3枚とも同じ骨格で、3列に収めるため左右の余白を32px、見出しを 1.1875rem
（特徴・こんなときにのカードと同じ目盛り）にしてある。
電話は番号を読ませる面なので `--mist` の淡い面のまま。フォーム2枚は押す先なので、
面ごと `--blue` のベタにして白文字・白丸の矢印にし、ボタンとして見せる（`.contact-card-solid`）。
フォーム2枚は見出しと矢印だけで、受付時間などの説明文は置かない（3列に入れると行が増えすぎるため）。
説明文のないカードは見出しと矢印を中央に寄せる。`FormCard` の `lines` は省略できる。
`/recruit` の応募フォームは2列なので説明文を残していて、そちらは左右に振り分ける。
フォームのURLが `【調整中】` のあいだはリンクにせず、ホバーの反応も付けない。

その下にアクセスマップを置く。Googleマップの埋め込み（iframe）を左、所在地・アクセス・TEL・
営業時間の表を右。埋め込みは住所のクエリ（`site.mapEmbedSrc`）で出していてAPIキーは要らない。
`next.config.ts` の CSP に `frame-src` で www.google.com と maps.google.com を通してある。
既定は `default-src 'self'` で、通さないと地図が無言で読み込まれない。
`site.mapEmbedSrc` が `【調整中】` のあいだは写真と同じプレースホルダの枠を出す。
地図を入れるとGoogleへの通信が発生するので、プライバシーポリシーの
「4. 外部サービスの利用」に明記してある。

`Contact` はTOPと `/service` に置く。`/recruit` の応募窓口は同じ `TelCard` と `FormCard` を使う。

**特徴カードの6項目**

| No | 見出し | TOP |
|---|---|---|
| 01 | 見離さない、見捨てない、諦めない | ○ |
| 02 | 精神・介護・医療・看取りのすべてに対応 | ○ |
| 03 | 主治医・病院との連携が早い | — |
| 04 | ご本人だけでなく、ご家族の相談にも応じます | — |
| 05 | 24時間のオンコール対応 | ○ |
| 06 | 在宅で必要な医療処置に幅広く対応 | — |

TOPに出すのは01・02・05の3つだけ。6項目とも本文は `/service` に置き、カードから遷移させる。

写真が調達できていないため、TOPのカードは写真枠を持たず、番号＋見出し＋本文の抜粋で組む。
抜粋は原稿の文をそのまま使う。写真が入るときは番号を写真に置き換える。

### `/about` アプロについて

構成は参照サイト <https://npoho-jin.com/about_us/> に合わせている。
写真の使い方だけ <https://happywood.or.jp/vision/> に寄せ、写真を減らして文章とアイコンで組んでいる。

1. メインビジュアル（全幅・下だけ角丸。ページで使う写真はこの1枚と代表挨拶だけ）
2. ページ見出し
3. ミッション（02シート）
4. ビジョン（02シート）
5. バリュー（軸＋行動指針5項目）
6. 代表挨拶（`docs/代表挨拶原稿.md`）
7. 会社概要（`site.ts` から生成）

**写真は冒頭のメインビジュアル1枚と代表挨拶の1枚だけ。**ミッション・ビジョン・バリューからは
外した（クライアント判断）。写真の点数が限られていて、同じ写真を各節に配るより
文章で読ませたほうが締まるため。外したぶんは `/service` に回している。

メインビジュアルは全幅で下だけ角丸。高さは `clamp(320px,30vw,560px)`（960px以下は 240px）。
ヒーローと同じで幅に追従させる。固定にすると広い画面ほど帯が細くなり、上下が落ちて顔が切れる。
`object-position` は `center 16%`。2560px でも2人の頭が切れない位置に寄せてある。
TOPのヒーローと同じ置き方だが、**写真はヒーローの3枚と別のものを使う。**
同じ写真だとTOPから移ってきたときに同じ絵が続く。`priority` を渡して遅延読み込みを外している
（ページ最初の1枚で、遅れると見出しより後に出るため）。

ミッションとビジョンは写真を持たず、英字ラベルを左の列（会社概要と同じ 200px・間 64px）に出し、
見出しと本文を右に置く。2つのあいだは罫線1本で区切る。理念ページの定番の組み方で、
面や囲みを足さずに余白と罫線だけで区切りをつくる（参考：baigie.me/company/mission、
kakaritsuke.co.jp/message）。ラベルは見出しの1行目に合わせて `0.55rem` 下げてある。
見出し（30px・行間1.7）とラベル（13.5px・行間1.6）で文字の天地が10pxずれるため。
960px以下は1カラムに落とし、下げをやめる。本文は `p` の 34em で列幅が決まる。
淡い面（`.wrap-panel`）に入れると文字の列が 468px まで落ちてビジョンの見出し
（原稿の1行が17文字）が原稿にない位置で折れるため、ミッションからバリューまでは
白地の `.wrap` に置き、色を敷くのは会社概要だけにしている。

行動指針の5項目はカードではなく罫線区切りのリスト。1カラムで、番号の代わりに
アイコン（`ValueIcon`）を左、見出しと本文を右に置く。参照サイトの運営方針と同じ並べ方。
**960px以下はアイコンを見出しの上に積む。**横に並べたままだと文字の列が282pxしか残らず、
いちばん長い見出し（16字）が折れて「ない」だけが行に残る。積めば全幅が使えて1行に収まる。
項目の見出しと軸の一文は、960px以下ではミッション・ビジョンと同じ19px（`1.1875rem`）に揃える。
セクション名（「行動指針」「会社概要」）は短いので30pxのまま。
`position:sticky` を使っていたのは写真の列で、写真を外したので sticky も外した
（代表挨拶の写真は sticky のまま。`.reveal` を sticky の祖先に付けないこと）。

バリューの軸の一文は `text-balance` で2行に割っている。素直に折ると「社会へ。」だけが次の行に残る。

参照サイトにある「企業理念」の一文に当たる原稿は02シートにない。足す場合は `site.ts` か
`src/content/about.ts` に原稿を追加してから出すこと（文言を作らない）。

### `/service` 事業紹介

1. メインビジュアル（`/about` と同じ置き方。写真はページごとに変える）
2. ページ見出し
3. サービス概要リード（写真は置かない）
4. こんなときにご相談ください
5. 私たちが行うこと（8項目。項目ごとにアイコン）
6. アプロの特徴（01〜04。写真つき）
7. 24時間対応／対応できる医療処置（淡い面）
8. 対応エリア（青ベタ面。図）
9. ご利用までの流れ（介護保険／医療保険。**連番を使うのはここだけ**）
10. お問い合わせ

TOPの特徴カード6枚からアンカーリンクで飛べるようにする。

**受け入れについて（「まずお受けして、そこから考えます」の独立ブロック）は外した**（クライアント判断）。
節が多く縦に長いため。同じ文はTOPの特徴の導入に出ている。原稿は `content/service.ts` に残してある。

**こんなときには、横長のカードを3枚縦に積む。**見出しを左（240px）、項目を右に置く。
3列に縦積みすると1列が長くなり、3本の縦列を目で追うことになって読みにくい。
横に寝かせれば1行が短くなり、上から順に読める。

一度カーソルで要約と項目を入れ替える形にしたが、外した（クライアント判断）。
読んでいた文が消えて何が起きたか分からないため。**この節に開閉も入れ替えも入れない。**

**カラーバランス。**白 → 淡い面（こんなときに）→ 白（私たちが行うこと・特徴）→ 淡い面（24時間対応）
→ 青ベタ（対応エリア）→ 白（流れ）の順。青ベタ面はページで対応エリアの1箇所だけ。
受け入れの一文を外したぶんの青をここで戻している。

**図にした2箇所。**

対応エリアは**実際の地図**（`public/images/tokyo-map.svg`）。対応する3市を `--blue` で塗り、
他の市区町村は `--blue-soft`、境は白い線。白い面に載せて、下に市名のピルと注記を置く。

**3市を中心に24km四方で切り取っている。**東京都の全域を出すと3市が横幅の1割ほどにしかならず、
どこのことか分からない。この寄せ方なら3市で横幅の4割を占め、隣接する市の形も一緒に見える。
上下左右とも都内で埋まる大きさでもある。

市名は地図の上にHTMLで重ねる。SVGの `<text>` に入れると画面幅に合わせて文字まで伸び縮みし、
スマホで読めなくなるため。位置はスクリプトが出す％をそのまま `areaLabels` に入れている。
600px以下は地図が小さく市の形から文字がはみ出すので出さない（市名は下のピルにも出ている）。
市名を並べるだけでは位置が伝わらず、初めて見る方が自分の地域か判断できない。
よくできている訪問看護のサイトは地図の図版で見せている（例：nagomizaitaku.jp）。
丸を横一列に並べる形と、市を角丸の面で並べた簡易地図も試したが、どちらも図として意味がなかった。

地図は国土交通省「国土数値情報（行政区域データ）」から起こしている。
作り直しは `scripts/make-tokyo-map.py`（使い方はファイル先頭のコメント）。
**対応エリアを変えたら地図も作り直し、`areaLabels` の位置も入れ直すこと。**
線は約35mまで間引いて 19KB に収めた（表示幅900pxで1px程度なので見た目は変わらない）。
`<img>` で読み込む（SVGは next/image を通しても軽くならない）。ページの下のほうなので遅延読み込み。
**出典表記は利用約款の条件。消さないこと。**国土数値情報は出典を書けば商用利用もできる。

流れは番号を共通モチーフの面（`.flow-no`）に入れ、次の番号まで縦線でつなぐ。
図形はモチーフの形と角丸の面だけで、新しい形は足していない。

### `/recruit` 採用情報

1. 採用キャッチ＋リード
2. 採用理念
3. 求める人物像（2種類を並列）
4. 働き方の特徴（5項目）
5. 教育・研修（4項目）
6. 福利厚生
7. 正直にお伝えしておきたいこと ← `--sand` を使う唯一のブロック
8. 募集要項（3職種。デスクトップは比較テーブル、モバイルはカード積み）
